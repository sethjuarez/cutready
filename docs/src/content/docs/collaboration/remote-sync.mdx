CutReady can sync your project with a **GitHub remote repository**, enabling
backup, multi-device workflows, and team collaboration. Remote sync is entirely
optional — solo users who don't need it see zero additional UI.

## Setting Up a Remote

1. Open **Settings** → **Repository** tab
2. Enter your remote URL (e.g., `https://github.com/you/your-project.git`)
3. Choose an authentication method
4. Click **Test Connection** to verify

### Authentication Methods

| Method | Description |
| --- | --- |
| **GitHub CLI (gh)** | Recommended. Uses your existing `gh auth` credentials |
| **Personal Access Token** | Enter a GitHub PAT with repo scope |
| **SSH Key** | Uses Draftline remote support with your system SSH keys |

<Aside type="tip">
  The GitHub CLI method is the easiest — if you have `gh` installed and
  authenticated, CutReady picks up your credentials automatically.
</Aside>

## Sync Status

Once a remote is configured, the changes popover shows one line of status:

| Status | Meaning |
| --- | --- |
| **Up to date** | Nothing to send and nothing new from the team |
| **N saves waiting to send** | Your saved versions haven't been sent yet |
| **Team has N new updates** | Teammates sent work you don't have yet |
| **Syncing…** | Checking, getting updates or sending |
| **Sync needs attention** | Something went wrong; the message below says what |

**Check** looks for new work without changing anything. **Get updates** brings
the team's work in. **Send** shares your saves; if you have unsaved changes it
asks you to save them as a version first.

<Aside>
  In a project inside a code repository, **Send** becomes **Send for review**
  and opens a pull request instead. See
  [Projects in a Code Repository](/collaboration/hybrid-projects/).
</Aside>

## Team Updates

You only ever name your own saves. When teammates have sent work, **Send** and
**Get updates** bring it in for you, with no extra prompt:

1. CutReady checks for the team's updates.
2. Your unsent saves are replayed on top of them, so history stays a straight
   line and your saves keep their names.
3. Send then shares your saves and reports, for example,
   _Sent ✓ (also picked up 2 team updates)_.

When replaying isn't possible, CutReady combines the two lines of work instead
and records it in History as **Brought in team updates**, listing what came in
and who sent it. That happens when:

- some of your saves were already shared;
- another timeline was started from a save that hasn't been sent yet, so
  replaying would leave that timeline behind;
- you and a teammate changed the same file.

Open previews, Compare tabs and file diffs follow the replayed saves
automatically.

## When You and a Teammate Change the Same File

Only a real overlap asks you anything. The prompt names the people and files,
for example _You and Dana both changed compass.sk_, and lets you keep yours,
keep theirs or edit the result. See [Merging & Conflicts](/collaboration/merging/)
for the full resolution panel.

## Shared Timelines

**Send** shares the timeline you're on. Timelines a teammate has shared appear
under **Shared timelines** in the timeline menu; pick one to make your own copy
and switch to it.

## Auto-Fetch

CutReady automatically fetches from the remote:

- **On project open** — Checks for new remote changes immediately
- **Every 5 minutes** — Periodic background fetch keeps counts fresh

Auto-fetch only downloads metadata — it doesn't modify your local files.
You always explicitly choose when to pull or sync.

## Opening a Pull Request

For published non-main timelines, CutReady offers an **Open Pull Request**
button that opens your browser to create a PR on GitHub. This integrates
your CutReady workflow with standard GitHub collaboration.

## Offline Resilience

CutReady works fully offline — all project data is local. When you're
offline:

- Saving, branching, merging, and all local operations work normally
- The sync status shows what's waiting to send
- When connectivity returns, **Send** catches up

## How This Relates to Git

Remote sync uses a normal GitHub repository as the transport, but CutReady keeps
the workflow at the Draftline level:

- **Snapshots** are the user-facing unit of saved work, not commits.
- **Timelines** are the user-facing unit of branching, not raw branch names.
- **Sync** transfers Draftline-managed snapshots and timeline refs.
- **Runtime state** stays local and is not pushed, including chat trajectories,
  locks, local UI state, and recording takes.

If you inspect the remote with Git tooling, you may see implementation details.
Do not edit them by hand unless you are intentionally debugging Draftline
storage.

## Progressive Disclosure

CutReady uses **progressive disclosure** for remote features:

| User Type | What They See |
| --- | --- |
| **Solo** (no remote) | Just the Snapshots panel — Save, Discard, Navigate |
| **Timelines** (no remote) | Timeline selector + graph, no sync UI |
| **Collaborator** (remote configured) | Sync status, Send, Get updates and shared timelines |

No git terminology appears in the default UI. CutReady uses "snapshots" not
"commits", "timelines" not "branches", "send" not "push", and "get updates" not
"fetch/pull". Team work comes in without anyone naming a merge.
